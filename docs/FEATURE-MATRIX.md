# Feature matrix

**Task:** S-06. **Updated:** 2026-11-14. **Describes:** the code on `main` at commit `50d4c80`, merged into branch `arsh/S-06-docs`.

One row for each acceptance criterion AC-01 to AC-20 and for each P0 item in `docs/PRD.md` section 4. Task IDs come from `scripts/tasks.json`. Where the PRD and `docs/SPEC.md` use different names, the row uses the SPEC name.

## Status words

| Status | Meaning |
|---|---|
| Built and tested with fakes | The code is on `main` and automated tests cover it with an in-process Postgres and fake providers. This alone does not prove it works live. |
| Verified against the real service | Run against the real service. The complete list is in `SECURITY_NOTES.md` section 2. A row says exactly which part was verified and where: on the deployed server at `https://abos-server.onrender.com`, or on a local server against the same real backend. |
| Not built | The code is not on `main`. |

A row can be built and tested with fakes and also have one part verified. The row then names that part. Everything else in the row is not verified.

Three things apply to every row.

- **The live checks cited here are script runs.** No run by a person at the web screens is recorded. The list of real checks names `scripts/live/run-demo.ts` for the pizza run on the deployed server. It signs in as the seeded owner and drives the server over HTTP. The checks on a local server match that script's other flows, and I have assumed it made them too. Where a row says "simulated call", the call was text through `POST /api/agents/:id/sim-call` on the real model with the real read and propose tools. No real phone call has been verified.
- **The web app run against the deployed server is not verified.** The web screens are covered by unit tests on fixtures.
- **The payment in the live run was a SIMULATED sandbox payment.** The script opened the Square order with UpdateOrder and paid it through the API with Square's sandbox test nonce. There was no card form and no real money. Paying through Square's hosted checkout page with a test card is not verified.

Test totals for this checkout are in `SECURITY_NOTES.md` section 3. In short: typecheck passed for all four workspaces, 2170 of 2172 server and package tests passed with 2 marked as expected failures (two known open defects), and all 600 web tests passed.

Paths are shortened: `server/` means `apps/server/`, `builder/` means `apps/server/src/builder/`, `db/` means `packages/db/test/`, and `contracts/` means `packages/contracts/src/`.
