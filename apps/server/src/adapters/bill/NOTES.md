# Lead wiring and decisions

- Register billPlugin on the public Fastify server outside authentication. Inject createBillCheckoutProvider into the approved executor checkout port. It accepts the stored Order or direct businessId, orderId and lines, awaits onLinkCreated, and resumes by key or saved bill ID.
- Implement CatalogPort from catalog_items, with variation availability and only currently allowed modifiers. Combine item and variation names in each row name. Implement VerifiedFactPort from a current owner-verified tax policy. Decide its fact key and add its validation elsewhere. Missing rate fails closed; zero must be explicit. USD only. Exclusive tax is 0 to 10000 basis points, rounded half up once per order using bigint.
- Arsh must add the durable BillStore migration and restricted-role query implementation. It needs unique idempotency key, bill ID and token hash constraints; an atomic insert that returns only the same-key winner; token-hash collision rejection; encrypted replay tokens; retained expiry tombstones; and a token-hash index. Private findByKey and findById queries must include the supplied business ID in SQL. The adapter also compares the returned business and order before revealing a URL. Public findByTokenHash remains global because the bearer token is intentionally the public credential. Never log keys, tokens or URLs. Inject node:crypto randomBytes, business lookup, public origin and a chosen lifetime. Use HTTPS in deployment. Supply approved pickupAt; direct callers that omit it get Not scheduled.
- Existing states are APPROVED, CREATING_CHECKOUT, PAYMENT_LINK_READY, optional MESSAGE_SENT, then PAYMENT_PENDING. Contracts have no honest terminal state for a bill alone. Decide and add a bill-ready or bill-issued terminal state, transitions, database guards and UI labels. End after local bill creation and optional approved delivery or QR display. Never enter PAID_VERIFIED or FULFILLMENT_READY, fabricate payment, start payment polling or trigger paid-order Sheets jobs.
- Add provider selection and neutral checkout references to contracts, storage, approval material and handlers separately. Compatibility fields squareOrderId and paymentLinkId both contain billId. They are local references, never Square IDs or payment evidence. Keep Square reconciliation away from them. Decide whether to add a local bill action or bridge square.checkout.create. Preserve exact-payload approval and stable keys.
- Replace payment wording in message templates, caller scripts and the dashboard with Demo bill. Sandbox. No payment is taken. Sending still requires approval of the exact payload and recipient. Decide separately whether unpaid bills should be reported; existing paid-order reporting stays disabled.
- Route-level silent logging suppresses Fastify URL logs. Redact bill URLs in upstream proxies, tracing and custom global hooks too. Register outside authentication. Set Fastify({ rewriteUrl: rewriteBillUrl }) at server construction. This exported helper normalizes malformed bill paths and every non-GET or HEAD bill request before URI decoding and logging, including invalid escapes and oversized tokens, so they receive the same 404. Preserve this behavior if composing another rewrite hook.
- Arsh must pass ResumeCheckoutInput.businessId and orderId only from the ownership-checked execution and approved order. They must never come from an arbitrary request body. The executor callback that persists a link mid-run must map to the checked save-checkout-references routine with the claimed business, worker and attempt, never direct DML on protected tables.
- Proposal for owner ratification: a live-call human fallback is allowed without per-call owner approval because it is not one of the four approval-gated external writes. It must fail closed unless the fallback number is a verified business fact, the published agent version handling the call enables human fallback, and the call is bound to an active call record for that business. Each provider call uses one stable key and is never retried with a new key.
