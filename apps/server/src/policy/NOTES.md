# B-07 integration notes

- Shared contracts require an E.164 messageRecipient for both order and booking payloads, and ContactSchema requires messageConsent=true even for qr_only. Supporting QR-only proposals without these fields requires changes in packages/contracts/src/schemas/orders.ts and approvals.ts. This engine follows those schemas and fails closed. QR-only proposals with valid contact data work and queue the message step as SKIPPED.
- decideApproval and expireApprovals use PostgreSQL now(). deps.now controls proposal timestamps and early expiry checks. Keep application and database clocks synchronized. The database remains authoritative for decisions and expiry sweeps.
- guardrail.refused requires callId, although fact edits and missing or cross-business executions may have no available call. Such events use the reserved correlation label call_policy in callId. Making callId optional and adding executionId and reasonCode in packages/contracts/src/events.ts would represent these refusals directly. Refusals for a nonexistent business cannot write an activity row because activity_events.business_id has a foreign key.
- resolvesConflictId is stored with the proposal in the approval row's `payload`, beside the hashed material (the database requires `payload` to contain the canonical material, and freezes it from insert). It is never part of the hash and never returned by the API. When `local.fact.update` runs, the engine reads it from the stored row and resolves that one conflict in the step's transaction, only for the same business, kind and key and only while it is open. New fact versions use the approved payload, never a mutable draft value.
- authorizeStep requires SQUARE_ENVIRONMENT=sandbox. Local bundle steps have no capability by contract; external steps require matching write or external_message registrations. Executors must use the guarded claim functions from @abos/db to enforce step sequencing and exclusive worker claims.
- No routes, environment files, dependencies or shared packages were changed. REST registration and real-provider execution belong to other tasks and were not exercised here.
