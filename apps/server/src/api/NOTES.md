# B-08 integration notes

- The health contract uses `connected`, `degraded` and `disconnected`, not the requested `ok` and `unconfigured`. Routes use `connected` or `disconnected`, with `detail` set to `ok` or `unconfigured`. This checks configuration only, not provider connectivity. Add the requested state names to packages/contracts in a separate contract change if needed.
- Health includes the requested additive `squareEnvironment: "sandbox"` field and the contract's `square.environment: "sandbox"`. The contract does not yet name the top-level field.
- The businesses, facts and catalog endpoint definitions omit pagination fields. These routes use the shared PaginationQuerySchema and return an additive nextCursor. Add those fields to their packages/contracts endpoint schemas so generated clients retain them. Reference lists are paged in memory; operational lists use SQL keyset pagination.
- LiveAgentSchema requires updatedAt even in the empty case. An empty response omits agent IDs and uses the first owned business and its updatedAt. No phone number configuration returns INTEGRATION_UNAVAILABLE.
- Approval Idempotency-Key responses are retained for 24 hours in the current server process, with concurrent requests sharing one promise. Restarting or running multiple instances needs a shared replay store and a packages/db migration outside this task's allowed scope. The injected engine must independently make repeated decisions safe.
- The real approval engine and Square catalog adapter are injected ports. Without them, writes return INTEGRATION_UNAVAILABLE. The in-memory engine is a test fake and is never the app default. No live provider or Supabase connection was tested; JWT tests use signed tokens and a stubbed JWKS, and database tests use the real migrations in PGlite.
- WEB_ORIGIN configures CORS, defaulting to http://localhost:3000. A production deployment must set it to the web origin. DATABASE_URL must be the service-role session connection; createPool requires verified TLS.
