# B-15 notes: things outside apps/server/src/voice and tools/real

1. **Register the plugin (app.ts, not edited).** One line: `await app.register(voicePlugin, { publicServerUrl, liveAgent, calls, toolsetFactory, twilioValidator: createTwilioRequestValidator(TWILIO_AUTH_TOKEN), openaiSocketFactory: createWsOpenAISocketFactory({ apiKey: OPENAI_API_KEY }), messageChannel, redactSecrets: [OPENAI_API_KEY] })`. The plugin registers `@fastify/formbody` and `@fastify/websocket` itself unless the app already has them. Both ways are tested (the second over a real localhost socket).
2. **env.ts (not edited)** needs `TWILIO_AUTH_TOKEN`, `OPENAI_API_KEY`, `MESSAGE_CHANNEL` and a required `PUBLIC_SERVER_URL` before the plugin can be wired.
3. **The capability rule differs from the brief, on purpose.** The brief says to refuse a session when the spec lists any write or external_message capability. Every real spec does: `AgentSpec.capabilities` holds the tools plus the executor bundle (fixtures `PIZZA_CAPABILITIES`, `BARBER_CAPABILITIES`), so that rule would refuse every call. `checkSessionCapabilities` instead refuses an unknown id, or any write or external_message capability that is not in the bundle of a propose capability the spec holds (for example `catalog.price.update`, or `message.checkout.send` without `order.propose`). Bundle capabilities never become tools, and the tool list is asserted with `assertToolCapabilities`. The check runs at the webhook (spoken refusal) and again on the socket (call ends `failed`).
4. **`webhook.rejected` is not written** on a bad Twilio signature (FLOWS B1, SPEC 2.9). The plugin has no activity-event port. It returns 403 and logs a warning. Add an events port, or let the calls port own it.
5. **Stream tokens live in memory** in the plugin instance (single use, 60 s, tied to the CallSid). SPEC 2.9 says the token is stored against the call; that matters only with more than one server process.
6. **docs/FLOWS.md B12 is out of date.** It says a caller who declines messages cannot finish an order. The SPEC 2.9 ruling and the contracts let them: no recipient, channel `qr_only`, the link shown at the counter. The prompt and the toolset follow the ruling.
7. **Not built here:** speaking the approval outcome to a caller still on the line (FLOWS 3.1, needs an executor event into the session), and `/webhooks/twilio/status`.
8. **Ports for other workers.** `CallsPort.startCall` must be idempotent on `providerCallId` (a retried webhook returns the same call). `OrderStatusPort.read` must return null for an order of another business or, when `callId` is given, another call. `ProposalPort` re-checks policy; the toolset already refuses unknown, expired and changed quotes and pickup times outside the snapshot's hours.
9. **Unverified:** the Twilio leg (TwiML, Media Stream events, marks, `clear`) has not run on a real call. The OpenAI session shape and events are the spike's, proven on 2026-11-13.
