## Required work outside this worker's directories

In that transaction, verify business, published version, active call, hours, quote or slot and immutable payload, and create the local proposal and approval together. Enforce unique `(business_id, call_id, operation_id)` and single use of an order quote. Return the same stored result for the same operation ID. Set `atomicOperations: true` only for that adapter. Without it, this module refuses proposal creation. No direct writes to approval_requests, action_executions, message_dispatches or sync_jobs are required by these ports.

2. **Arsh, database and approval engine owner: uncertain operation lookup (R2).** The module reserves a quote synchronously before proposal creation and passes one stable `operationId`. A timeout, exception or malformed result leaves it reserved. Retries fail closed and never create a second operation. Recovery needs a scoped routine returning the persisted result of that exact operation, or authoritative evidence that nothing was stored. That routine and its adapter are outside this scope. Until they exist, the caller cannot retry an uncertain proposal on the same quote. Reservations are bounded and disposed at hangup. Booking creation is also locked while its result is uncertain. Executor lease renewal, NEEDS_REVIEW resolution from provider evidence, checkout reference persistence, booking verification and stale lease recovery belong to the lead's migration and executor adapters. Restoring messages requires server-owned evidence bound to this active call, published version, exact recipient, completed digit-by-digit playback and a later affirmative caller consent turn. Decline and recipient change must invalidate it. Define and ratify that evidence contract, wire its trusted producer, and add real confirmation-event tests before enabling a message channel. ## Human fallback proposal for the owner to ratify

Handing a live call to a person is not one of the four approval-gated writes: Square, a customer message, Calendar or Sheets. It does not require per-call owner approval. It is allowed only when the fallback number is a verified business fact, the published agent version handling this call enables human fallback, and the call is bound to an active call record for that business. One provider call must use one stable idempotency key across every retry. This is a proposal for Arsh to ratify. This module exposes no transfer tool or provider transfer call, so it fails closed until trusted eligibility and provider ports implement all three checks. No test-client factory was added to production code; all injected test clients live in test-only files.

## Local policies and verification limits

- Both audio directions include the next encoded frame in the queued-byte limit and fail the session instead of staging more audio. Pending marks and retained playback items are bounded. Generation-end events retire completed offsets and canceled tombstones once playback drains; absent generation-end events, 128 retained items fail the session. Shutdown clears playback and aborts invocations.
- Accepted stream credentials are registered for redaction. Provider types/codes and exception names/codes use fixed enumerations with unknown_error fallback. There is no syntax-only metadata exemption. Untrusted port error prose is replaced with fixed local wording. Voice HTTP errors do not echo URLs or parser input.
- Replies require plain spoken sentences with no Markdown, asterisks, lists or headings. Server-authored speech, greetings and status instructions strip emphasis delimiters while preserving tool identifiers in instructions.
- OpenAI acceptance of injected system status items, echoed response metadata, zero-length truncation and generation-end event ordering remains unverified against a real provider. Twilio behavior after closing a Media Stream, actual speech delivery and live read-back remain unverified. Tests prove socket handling and sent instructions with fakes, not delivered speech or actual phone hangup.
- The in-memory stream credential store deduplicates one process. Cross-process uniqueness, event persistence and call-state enforcement remain adapter duties. No `/webhooks/twilio/status` handler is implemented here; the relay polls call status.
- docs/FLOWS.md B12 needs the lead's correction: declined messages do not block an order. The checkout link is shown at the counter with `qr_only`.
